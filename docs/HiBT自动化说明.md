# HiBT 事件合约自动化说明

> **重要声明**  
> - HiBT **官方未提供**面向第三方的正式量化 / 自动化交易 API。  
> - 本项目中的 HiBT 相关能力，是基于公开资料中的 **Web 端接口形态** 做的研究与联调封装，**仅供学习与自用测试**。  
> - 使用非官方方式下单存在封号、失败、资金损失等风险，**后果自负**。  
> - 官方曾提示警惕第三方“量化工具”，请勿向不明平台提交账号密码。

相关代码位置：

- App：`android/` → 底部导航 **「下单」**
- 可选 PC 微服务：`services/hibt`（默认端口 8012）

默认 **Dry-Run（模拟）开启**，不会真实下单。只有你主动关闭 Dry-Run 并开启「自动化」后，才可能向 HiBT 发真实请求。

---

## 1. 整体流程（App）

1. 安装 `android-app` 构建的 APK，打开 **下单** 页。  
2. 按下文从浏览器复制凭证，填入：
   - API Base（一般 `https://api.hibt0.com`）
   - Authorization
   - x-auth-token
   - v 参数（若请求 URL 里有则一并复制）
3. 点 **测试连通性**，查看是否返回余额 / 持仓类信息。  
4. 确认：
   - **Dry-Run** 建议先保持开启  
   - 需要时再开 **自动化下单**、**AI 评估**、阈值与默认金额（默认 3）  
5. 行情页启动策略 + 后台监控后，出现信号时才会按规则尝试下单（Dry-Run 时只记日志式结果，不真下单）。

周期与 **行情页头部** 选中的 5m / 10m / 30m / 1h 一致。

## 2. 如何获取 Token

凭证来自你在 **电脑浏览器** 登录 [hibt.com](https://hibt.com) 之后的 Web 会话，不是 App 里“一键登录”。

### 2.1 推荐步骤（Chrome / Edge）

1. 用 **日常交易账号** 在电脑浏览器打开 https://hibt.com 并完成登录（含邮箱/2FA 等）。  
2. 进入 **事件合约** 相关页面，确保能正常看到行情/下单。  
3. 按 `F12`（或右键 → 检查）打开 **开发者工具**。  
4. 切到 **Network（网络）** 面板，勾选 **Preserve log（保留日志）**。  
5. 在页面上随便操作一次（刷新事件合约页、点一下持仓等），让列表出现对 `api.hibt0.com`（或当前站点实际 API 域名）的请求。  
6. 在请求列表中点开任意 **已登录状态** 的 XHR/Fetch 请求，查看 **Request Headers（请求头）**。  
7. 复制以下字段（名称可能略有大小写差异，以实际为准）：

| 填到 App 的项 | 一般在浏览器里的位置 |
|---------------|----------------------|
| **Authorization** | 请求头 `Authorization`（常为较长 JWT 或 Bearer 串） |
| **x-auth-token** | 请求头 `x-auth-token` |
| **v** | 请求 URL 查询参数 `?v=...`（有则复制整段 v 的值） |
| **API Base** | 一般为 `https://api.hibt0.com`（以你抓到的 host 为准） |

8. 粘贴到 App **下单** 页对应输入框，点 **测试连通性**。

### 2.2 安全注意

- Token 等价于 **已登录会话**，泄露等于账号被他人操作。  
- **不要** 把 token 提交到公开 Git 仓库、截图发群、发给陌生人。  
- 不要在公共电脑上长期保存。  
- 若怀疑泄露：在官网 **改密码、退出所有会话、重新登录**，旧 token 通常会失效。

### 2.3 为什么不是账号密码直登？

App / 本仓库 **不鼓励、也不默认实现** 用邮箱密码 + TOTP 在第三方里模拟登录。  
那样需要保存密码与二次验证密钥，风险更高。当前设计是：**你在官方页面登录后，只拷贝会话头**。

## 3. 是否需要一直开着浏览器？

| 问题 | 说明 |
|------|------|
| **抓 token 时** | 需要打开浏览器登录，用开发者工具复制。 |
| **App 运行、后台监控时** | **不需要** 一直开着浏览器。Token 已写在 App 本地配置里，由 App 直接请求 API。 |
| **Token 过期后** | 需要再开浏览器登录，重新复制一轮 token。有效期 **不固定**，可能数小时到数天，以实际失效为准。 |
| **电脑关机** | 不影响手机 App（只要 token 仍有效）。 |
| **同一账号多端** | 若官网强制单点登录或刷新会话，可能导致手机侧 token 突然失效，需重抓。 |

**结论：**  
日常自动化 **不依赖** “电脑浏览器一直挂着”；只依赖 **token 是否仍有效**。失效后必须人工重新登录官网并更新 App 配置。

## 4. 自动化逻辑（App 内）

在策略产生 **买入 B / 卖出 S** 信号，且：

1. 「开启自动化下单」为开，且  
2. 通过 AI 评估（若开启）：用 LLM 估计当前周期方向胜率，**≥ 你设的阈值** 才下单；未开 AI 时按是否开启自动化直接处理，且  
3. 非 Dry-Run 时才会发真实 `place` 请求  

下单参数大致对应：

- `symbol`：如 `btc_usdt` / `eth_usdt`  
- `direction`：涨 / 跌  
- `amount`：默认金额（界面默认 3）  
- `timeUnit`：与行情周期分钟数一致（5 / 10 / 30 / 60）

接口形态参考公开逆向说明中的 Web 下单路径（如 `/option/option-order/place`），**随时可能被官网改版导致失效**。

## 5. 注意事项清单

1. **先 Dry-Run**：确认信号与参数无误再考虑真实下单。  
2. **小额**：真实金额从最小档试起（界面默认 3，仍可能亏损）。  
3. **非官方**：接口变更、风控、验证码、地区限制都可能导致失败。  
4. **无收益承诺**：历史回测胜率 ≠ 实盘；AI 胜率只是模型估计。  
5. **后台与省电**：Android 需允许通知、忽略电池优化，否则进程被杀后无法监控。  
6. **合规与条款**：请自行阅读 HiBT 用户协议；禁止用于违规用途。  
7. **本项目不承担** 因使用自动化造成的任何资金或账号损失。

## 6. 可选：PC 微服务

```bash
cd services/hibt/app
pip install fastapi uvicorn httpx
python main.py   # :8012
```

- `POST /api/v1/test`：测 token  
- `POST /api/v1/place`：下单（`dry_run: true` 默认）  

手机端 **不依赖** 该服务即可完成配置与 Dry-Run；微服务便于在电脑上调试。

## 7. 故障排查

| 现象 | 可能原因 |
|------|----------|
| 测试连通失败 | token 过期、复制少了 Bearer 前缀、API Base 错误、网络/地区限制 |
| Dry-Run 正常、真实失败 | 官网改接口、缺 v 参数、风控、金额/品种不支持 |
| 有信号不自动下单 | 未开自动化、AI 阈值过高、策略未启动、后台被系统杀掉 |
| 余额显示 “-” | 账户接口路径与当前官网不一致，但 token 仍可能用于下单；以真实下单结果为准 |

---

**再次提醒：** 获取 token 需要浏览器登录一次；跑自动化 **不必** 一直开着浏览器，但 token 会过期，需定期更新。优先使用 Dry-Run，谨慎真实下单。
