# Crypto Agent 生产部署指南

## 目标流程（推荐）

```
1. git clone 公开仓库（代码）
2. 建立「私有仓库」（只放 .env 模板说明 + persist 持久化文件）
3. 创建 GitHub PAT（最小权限）
4. 配置 GitHub Actions Secrets → 自动部署到服务器
5. 浏览器访问公网地址
6. 在「基础设置 → 密钥与连接测试」写入 PAT（仅 Cookie）
7. 点击「拉取持久化」→ 服务器 data/persist 恢复
8. 正常使用（推送可按需手动；定时推送需服务器侧可选 PAT，默认不落盘）
```

**安全原则：PAT 不写进服务器磁盘、不进 Config 库、不进公开仓库。**  
仅存在用户浏览器 Cookie；调用 Sync 时通过请求头 `X-GitHub-PAT` 临时使用。

---

## 一、公开代码仓库

```bash
git clone https://github.com/PUITO/crypto-agent.git
cd crypto-agent
```

代码可公开；**不要**把真实 `.env`、PAT、`data/persist` 提交到此仓库。

---

## 二、建立私有仓库（配置 + 持久化）

1. 在 GitHub 新建 **Private** 仓库，例如：`yourname/crypto-agent-private`
2. 建议目录结构：

```
persist/
  config/runtime_config.json
  market/
  datasets/
  chart/
  plugins_state/
README.md          # 说明本仓库仅备份，无业务代码
```

3. （可选）放一份 **脱敏** 的 `env.example`（无密钥），真实密钥只放在部署机环境变量或 Actions Secrets。

首次可在已有运行实例上「推送持久化」生成 `persist/` 树，或空仓库等第一次 pull/push。

---

## 三、创建 PAT

GitHub → Settings → Developer settings → Personal access tokens

**最小权限建议（经典 PAT）：**

| 权限 | 用途 |
|------|------|
| `repo`（私有库读写） | 读写 `crypto-agent-private` 的 persist |

**不要**给 `admin`、不要用于公开仓库写权限以外的多余 scope。

Fine-grained token：仅授权该私有仓库的 Contents: Read and write。

---

## 四、GitHub Actions 部署

### 4.1 在「公开代码仓库」配置 Secrets

路径：公开仓库 → Settings → Secrets and variables → Actions

| Secret 名称 | 说明 |
|-------------|------|
| `DEPLOY_HOST` | 服务器 IP 或域名 |
| `DEPLOY_USER` | SSH 用户 |
| `DEPLOY_SSH_KEY` | 部署用私钥 |
| `DEPLOY_PATH` | 服务器项目路径，如 `/opt/crypto-agent` |
| `PUBLIC_BASE_URL` | 公网入口，如 `https://agent.example.com` |
| `GITHUB_SYNC_REPO` | 私有仓 `owner/name`（**不含 PAT**） |

**不要**把 `GITHUB_PAT` 配成服务器长期文件；若必须做机房定时备份，使用单独「备份机器人」账号与只读/有限权限，且与用户 Cookie PAT 分离。

### 4.2 工作流

见 `.github/workflows/deploy.yml`：

- 在 `main`/`master` 推送或手动 `workflow_dispatch` 时触发
- SSH 到服务器：`git pull` → 安装依赖 → `./scripts/start_prod.sh`
- 输出公网访问地址（`PUBLIC_BASE_URL`）

### 4.3 服务器首次准备

```bash
sudo mkdir -p /opt/crypto-agent
sudo chown $USER:$USER /opt/crypto-agent
git clone https://github.com/PUITO/crypto-agent.git /opt/crypto-agent
cd /opt/crypto-agent
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# 编辑 .env：GITHUB_SYNC_REPO=your/crypto-agent-private
# 不要写入 GITHUB_PAT
./scripts/start_prod.sh
```

反向代理示例（Nginx）：

```nginx
server {
  listen 80;
  server_name agent.example.com;
  location / {
    proxy_pass http://127.0.0.1:8000;  # Gateway
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
  location /app/ {
    proxy_pass http://127.0.0.1:5173/;  # 或静态 frontend/dist
  }
}
```

## 五、公网访问地址（部署后）

| 入口 | 地址 | 说明 |
|------|------|------|
| 统一 API | `https://<你的域名>/` | Gateway :8000 |
| API 文档 | `https://<你的域名>/docs` | |
| 健康聚合 | `https://<你的域名>/api/v1/health/all` | |
| 前端 | `https://<你的域名>/app/` 或静态托管 | |
| Sync | `https://<你的域名>/sync/...` | 需浏览器带 PAT 头 |
| Notify | `https://<你的域名>/notify/...` | |

GitHub Action 日志中会打印 `PUBLIC_BASE_URL`，便于确认。

---

## 六、访问后配置 PAT 并恢复数据

1. 打开前端 → **基础设置**
2. 滚动到 **「密钥与连接测试」**
3. 填写私有仓 `owner/repo` + PAT → **保存到 Cookie**
4. **测试 PAT** → 应显示仓库可访问
5. **拉取持久化** → 服务器 `data/persist` 从私有仓恢复
6. 按需 **测试** HF / Ollama / OpenAI / Binance / Webhook

之后可正常交易分析；需要备份时点 **推送持久化**。

## 七、配置项「测试」按钮说明

| 测试项 | 接口 | 验证内容 |
|--------|------|----------|
| GitHub PAT | `POST /sync/api/v1/test-pat` | 私有仓可达（PAT 仅请求头） |
| HuggingFace | `POST /config/api/v1/config/test-connection` type=hf | Token 有效 |
| OpenAI 兼容 | 同上 type=openai | API Key |
| Ollama | 同上 type=ollama | 本地/内网服务 |
| Binance | 同上 type=binance | 公共行情 |
| 通知 | `POST /notify/api/v1/test-channel` | Webhook/TG/EmailJS |

## 八、安全清单

- [ ] 公开仓无 `.env`、无 PAT、无 `data/persist` 真实数据  
- [ ] PAT 仅 Cookie / 请求头，服务器默认不落盘  
- [ ] 私有仓仅备份 persist  
- [ ] 部署 SSH 密钥仅 Actions Secret  
- [ ] 生产关闭 `DEBUG`，Gateway 前加 HTTPS  
- [ ] 定期轮换 PAT  

---

## 九、故障排查

| 现象 | 处理 |
|------|------|
| 拉取 401 | Cookie 无 PAT 或过期，重新保存并测试 |
| 拉取 400 缺 repo | 填写 owner/repo 或设置环境变量 `GITHUB_SYNC_REPO` |
| Action 部署失败 | 检查 `DEPLOY_*` Secrets 与服务器 SSH |
| 服务不健康 | `./scripts/status.sh` 或前端「健康运维」页 |
