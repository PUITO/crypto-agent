# 开发与调试

## 脚本

| 脚本 | 用途 |
|------|------|
| `scripts/start_dev.sh` | 开发后台启动全部/单个 |
| `scripts/start_prod.sh` | 生产多 worker |
| `scripts/stop_all.sh` | 停止 |
| `scripts/status.sh` | 状态 |
| `scripts/run_service.sh <name>` | 前台单服务 |

公共逻辑：`scripts/lib/common.sh`（服务列表、PID、端口探测）。

## VS Code

1. 安装推荐扩展（`.vscode/extensions.json`）
2. 使用仓库 `.venv`（`.vscode/settings.json` 已指向）
3. **运行和调试**：
   - 单服务：`Service: Data` / `Agent` / …
   - 组合：`Debug: Core`、`Debug: Trading Path`、`Debug: All Backend`

`PYTHONPATH=libs` 已配置。断点可打在 `services/*/app`。

## 新增微服务

1. 复制 `templates/service_template`（若存在）或参照 `services/log`
2. 使用 `BaseServiceSettings`、`setup_logging`、`health_router`
3. 登记端口到：Gateway、`scripts/lib/common.sh`、Ops `SERVICE_SPECS`、文档表格
4. 需要持久化时写入 `common.persist.path_for("namespace", ...)`

## 共享库

- `libs/common/config.py` — 设置基类与服务 URL
- `libs/common/logging.py` — 控制台 + 文件 + 远程 Log
- `libs/common/persist.py` — 统一持久化路径
- `libs/common/remote_config.py` — 拉 Config 服务
- `libs/common/health.py` / `exceptions.py`

## 日志

- 本地：`logs/{service-name}.log`
- 集中：Log Service；Ops 查日志优先走集中日志
